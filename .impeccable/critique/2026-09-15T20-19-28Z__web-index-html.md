## Overall Impression

Yomi has a clean functional skeleton and a good reader-first instinct, but it currently presents itself as a generic dark manga catalog. The single biggest opportunity is to make “continue reading quickly” unmistakable from the first screen while improving the confidence and accessibility of every state transition.

## What's Working

- The core information architecture is compact: Home, Search, and Library are easy to understand, with detail and reader views entered contextually.
- The reader supports both continuous and page-by-page modes, hides chrome for immersion, and includes previous/next chapter navigation.
- Library progress is represented with resume labels, read states, new-chapter badges, sorting, and backup/export paths—strong foundations for a personal-use product.

## Priority Issues

### [P1] Perceived speed is represented as waiting, not progress

**Why it matters:** A spinner-only home, search, detail, and chapter experience makes network latency feel like app latency. The stated goal is “faster,” and the first impression currently provides no useful content while requests resolve.

**Fix:** Add skeletons that preserve cover/card geometry, stale-while-refresh content where safe, explicit empty states, and a prominent “continue reading” entry point that can render from local state before remote data arrives.

**Suggested command:** `/impeccable optimize web/index.html`

### [P1] Icon-only controls and gesture behavior are under-explained and under-labeled

**Why it matters:** Back, reader mode, and tap zones rely on glyphs or invisible interaction conventions. Keyboard focus styling is absent, and the reader’s chrome toggle is discoverable only by experimentation.

**Fix:** Add accessible names and visible tooltips or first-use hints, use semantic labels for mode controls, add `:focus-visible` states, and ensure touch targets and contrast remain strong in every reader state.

**Suggested command:** `/impeccable harden web/index.html`

### [P1] The home screen does not foreground the user’s actual job

**Why it matters:** “Popolari” and “Aggiornati di recente” are acquisition shelves, not the personal reader’s next action. A returning user must browse before finding what they were reading.

**Fix:** Lead with “Continua a leggere” when local progress exists, show the current chapter and progress, and make discovery shelves secondary. Give the empty library a direct search action instead of only explanatory copy.

**Suggested command:** `/impeccable layout web/index.html`

### [P2] Product character is generic and the typography has no authored voice

**Why it matters:** The dark surface, rounded cards, system font, pink/yellow accent pairing, and emoji placeholders do not communicate why this is Yomi rather than another manga catalog.

**Fix:** Establish a distinct visual system around the Yomi name and reading ritual—stronger type hierarchy, intentional accent roles, and a more deliberate treatment for progress and chapter recency—while keeping the restrained reader focus.

**Suggested command:** `/impeccable typeset web/index.html`

### [P2] Backup language overpromises safety and hides the operating model

**Why it matters:** “Restano al sicuro” conflicts with the documented open, shared backup endpoint. Import has no confirmation or conflict explanation, so a user can misunderstand what is protected or overwritten.

**Fix:** Replace absolute safety wording with precise personal-use language, disclose shared-server behavior in settings, show last sync and failure state, and confirm before import/merge operations.

**Suggested command:** `/impeccable clarify web/index.html`

## Persona Red Flags

**Returning mobile reader:** Home does not show the next unread chapter first; they must enter the library or search again. Reader mode and tap-to-hide behavior are not taught.

**Power user:** There are no visible keyboard shortcuts or command-level affordances for reader navigation, and the generic spinner gives no indication of which request is blocking progress.

**First-time user:** The empty library tells them to add manga from details but offers no direct search CTA. Icon-only back/settings/mode controls and emoji placeholders make the interface feel less finished and less self-explanatory.

## Minor Observations

- `web/manifest.webmanifest` describes the source as MangaDex while the product and backend use MangaWorld; this is a trust-breaking copy inconsistency.
- There are no visible `:focus-visible` rules in the stylesheet.
- Read chapters use reduced opacity, which may weaken scanability and contrast for completed items.
- The fixed bottom tab bar is optimized for mobile but leaves the desktop shell feeling like a stretched phone layout.
- The detector’s bounce easing at `web/styles.css:270` should be replaced with smooth deceleration.
